**版本**: 1.0
**日期**: 2026-08-28
**作者**: Sarah (Product Owner)
**质量评分**: 90/100

---

## 执行摘要

目前 JASM 用户要玩鸣潮 mod，必须先手动完成一套繁琐的准备工作：下载安装 XXMI 注入器、安装 WWMi（Wuthering Waves Model Importer）游戏包、手动在首次启动页填写「3Dmigoto 文件夹」和「Mods 文件夹」两个路径，还要让 JASM 与 XXMI 打通游戏启动。对于国内用户，从 GitHub 下载安装包本身就常因网络问题失败。

本特性新增「一键配置 Mod 启动环境」功能：应用自动检测游戏安装位置，从国内可直连的对象存储/CDN 下载 XXMI 与 WWMi 包，自动解压安装到默认目录（游戏所在盘 `盘符:\XXMI\WWMI`），校验安装完整性，并把两个路径自动填入 JASM 设置。用户从首次启动到 mod 加载成功，全程无需手动下载、解压或填路径。

---

## 问题陈述

**现状**: 首次启动页要求用户手动选择两个文件夹，说明文字引导用户「请先自行安装模型注入器」；从 GitHub 下载 XXMI/WWMI 对国内用户不友好；安装目录结构与 JASM 路径要求不透明，新手极易配错。

**解决方案**: 内建一键向导，串起「检测游戏 → 拉取版本清单 → 下载安装 XXMI+WWMi → 校验 → 自动填路径 → 接通启动」的完整链路。

**预期影响**: 将首次配置从「需要看教程、约 10 分钟 + 可能失败」压缩到「一键、几分钟内完成」，把新手配置失败率降到接近 0。

## 用户画像

### 主要：JASM 新用户（首次配置 mod）
- **角色**: 想给鸣潮装皮肤的新手玩家
- **目标**: 最快速度跑通「开游戏 → mod 生效」
- **痛点**: 不懂 XXMI/WWMI 是什么、GitHub 下载卡住、两个路径不知道填什么
- **技术水平**: 初级~中级，会装游戏和 JASM，但不想碰命令行/手动解压

### 次要：已安装环境的回归用户
- **角色**: 已手动配好环境的玩家
- **目标**: 不想重复劳动，希望环境升级/修复一键完成
- **痛点**: 游戏更新后 WWMI 失效、环境损坏要重装
- **技术水平**: 中级~高级

## 用户故事与验收标准

### Story 1：首次启动自动识别已有环境

**作为** JASM 新用户
**我希望** 打开 JASM 时，如果 mod 环境已装好，两个路径被自动填好
**以便** 不用手动找文件夹

**验收标准:**
- [ ] 进入首次启动页时自动检测 `盘符:\XXMI\WWMI\WWMI Loader.exe` 是否存在
- [ ] 存在时，「3Dmigoto 文件夹」自动填入 `XXMI\WWMI`，「Mods 文件夹」自动填入 `XXMI\WWMI\Mods`
- [ ] 自动填好后用户仍可手动修改，校验器行为不变
- [ ] 未装好时不填入，并显示「一键配置 Mod 环境」入口

### Story 2：一键安装完整环境

**作为** JASM 新用户
**我希望** 点击「一键配置」后应用自动完成全部安装
**以便** 无需手动下载解压

**验收标准:**
- [ ] 自动检测鸣潮安装位置；失败时弹出目录选择器回退
- [ ] 从远程版本清单拉取 XXMI 与 WWMi 包信息
- [ ] 依次下载、SHA256 校验、解压 XXMI 到 `<游戏盘>:\XXMI`、WWMi 到 `<游戏盘>:\XXMI\WWMI`
- [ ] 安装完成后自动校验 `WWMI Loader.exe`、`Mods` 文件夹、`d3dx_user.ini` 可写
- [ ] 完成后两个路径自动填入并保存，用户只需点「保存」

### Story 3：失败可续传、可重试

**作为** 任何用户
**我希望** 下载中断后能断点续传，失败的步骤可单独重试
**以便** 弱网环境下也能完成安装

**验收标准:**
- [ ] 下载支持断点续传（记录已下载字节）
- [ ] 某一步失败时保留已完成产物，仅标记失败步骤
- [ ] 提供「重试失败步骤」操作，不重复已成功步骤
- [ ] 解压前校验下载包 SHA256，不完整则提示重新下载

### Story 4：智能幂等与更新

**作为** 已安装环境的用户
**我希望** 重复点击时被提示「已是最新 / 可更新 / 可修复」
**以便** 不盲目重装

**验收标准:**
- [ ] 对比本地已装版本与版本清单，检测到已最新时提示并可跳过
- [ ] 有新版时提示可更新；环境损坏时提示可修复
- [ ] 分别检测 XXMI 与 WWMi，只处理缺失/过期的那一个

### Story 5：版本兼容检查

**作为** 任何用户
**我希望** 安装/更新前检查 WWMi 与鸣潮游戏版本是否匹配
**以便** 避免装完用不了的尴尬

**验收标准:**
- [ ] 版本清单携带 WWMi 对应的游戏版本号
- [ ] 检测到游戏版本与包版本不匹配时弹警告，用户可确认继续
- [ ] 游戏版本检测失败时不阻断安装，仅提示

### Story 6：接通游戏启动

**作为** 已配置环境的用户
**我希望** JASM 启动游戏时自动运行 WWMI Loader.exe
**以便** 开箱即玩

**验收标准:**
- [ ] 从 JASM 启动游戏时，自动先启动 `WWMI Loader.exe`（或走 XXMI 官方启动路径）
- [ ] 配置完成后提供「测试启动」引导，验证一次成功
- [ ] 游戏进程结束后 loader 正常退出，无残留进程

## 功能需求

### 核心功能

**Feature 1：环境自动检测（DetectionService）**
- 描述: 检测三件事——鸣潮游戏安装位置、本地 XXMI/WWMI 是否已装、版本与完整性。
- 用户流程: 进入首次启动页/点一键配置 → 自动检测 → 呈现状态。
- 边界情况:
  - 游戏未安装 / 检测失败 → 弹目录选择器手动指定；取消则中止
  - 本地已有 XXMI 但无 WWMi → 只装 WWMi
  - 本地环境损坏（缺 Loader.exe / 校验失败）→ 标记「可修复」
- 错误处理: 每项检测独立返回结果与原因，互不阻塞。

**Feature 2：版本清单解析（VersionManifestService）**
- 描述: 从 CDN 拉取远程版本清单 JSON，提供各包下载 URL、版本号、SHA256、大小、匹配的游戏版本。
- 用户流程: 点一键配置 → 拉取清单 → 展示各包状态（需下载/已最新/可更新）。
- 边界情况: 清单拉取失败 → 提示网络错误并允许重试；清单格式错误 → 视为 CDN 配置问题并提示维护者信息。
- 错误处理: 清单 URL 可在 `appsettings.json` 配置，缺省时功能禁用并提示。

**Feature 3：下载与安装（InstallService）**
- 描述: 断点续传下载 → SHA256 校验 → 解压到目标目录；XXMI 到 `盘符:\XXMI`，WWMi 到 `盘符:\XXMI\WWMI`。
- 用户流程: 向导展示每步进度与日志。
- 边界情况: 目标盘写权限不足 → 自动触发 UAC 提权（复用 Elevator 提权模式）完成安装；下载中断 → 断点续传；解压失败 → 保留压缩包，可重试。
- 错误处理: 任一步失败不自动回滚（断点续传模式），用户可就地重试。

**Feature 4：路径自动配置**
- 描述: 安装完成后把 `XXMI\WWMI` 填入 MI 文件夹、`XXMI\WWMI\Mods` 填入 Mods 文件夹，并写入 `ModManagerOptions`。
- 用户流程: 向导成功 → 返回首次启动页 → 两字段已填 → 用户点保存。
- 边界情况: 自定义安装位置时按实际路径计算；`WWMI\Mods` 不存在（包内未带）则创建。
- 错误处理: 保存失败时保留已填值并提示重试。

**Feature 5：启动整合**
- 描述: JASM 启动游戏时自动携带 WWMI Loader，实现开箱即玩。
- 用户流程: 在 JASM 点启动游戏 → loader 先行启动 → 游戏进程运行。
- 边界情况: loader 已在运行则不重复启动；游戏未配置环境则保持现状。
- 错误处理: loader 启动失败时提示，但不阻止游戏本身启动（降级）。

### 不在本期范围
- 多游戏支持（原神/绝区零等）——本期仅鸣潮 WWMi，架构上为后续预留
- 多语言版本清单管理面板（维护者 UI）
- 自动更新 JASM 自身
- 离线安装包仓库/镜像

## 技术约束

### 性能
- 下载支持断点续传与并发；大包（数百 MB）下载不阻塞 UI
- SHA256 校验以流式进行，避免内存峰值

### 安全
- 所有安装包下载后强制 SHA256 校验，避免篡改/损坏
- 盘根目录写入需要时自动 UAC 提权，仅限安装步骤
- 版本清单经 HTTPS 拉取

### 集成
- **CDN/对象存储**: 国内可直连；配置一个基础 URL（appsettings.json），清单与包都放这里
- **game.json**: 扩展字段描述每个游戏的 MI 包（包名、loader exe、目标子目录）
- **ModManagerOptions**: 复用现有 `GimiRootFolderPath` / `ModsFolderPath` 配置
- **StartupViewModel**: 路径自动填充接入点
- **ElevatorService**: 复用提权模式处理盘根目录写入
- **游戏启动**: 接入现有游戏启动流程

### 技术栈
- WinUI 3 + .NET 9.0；CommunityToolkit.Mvvm；WinUI3Localizer（中/英文案）
- 解压复用现有 SharpCompress / 内置 7-Zip 能力
- 下载复用现有 HttpClient 基础设施

- 「测试启动」引导验证

**MVP 定义**: 让一个新用户在无人指导、无 GitHub 访问的情况下，从首次启动到 mod 生效，全程 ≤3 分钟。

## 风险评估

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| 国内 CDN 不稳定/限速 | 中 | 高 | 断点续传 + 分块重试；可配置备用 CDN |
| 杀毒软件误报 WWMI Loader.exe | 中 | 中 | 安装说明内附白名单指引；SHA256 校验保证文件可信 |
| 游戏更新导致 WWMI 失效 | 中 | 高 | 版本兼容警告 + 维护者及时更新清单 |
| 盘根目录写入权限/防火墙限制 | 低 | 中 | 自动 UAC 提权；失败时清晰提示 |
| 包体积大导致下载体验差 | 中 | 中 | 显示进度、速度与已下载大小；支持后台/暂停 |
| 用户已有手动环境，路径冲突 | 中 | 中 | 智能幂等，绝不覆盖用户已有配置除非确认 |

## 附录

### 版本清单 JSON 草案（维护者发布用）

```json
{
  "manifestVersion": 1,
  "packages": {
    "xxmi": {
      "version": "1.0.0",
      "downloadUrl": "https://cdn.example.com/xxmi/xxmi-1.0.0.zip",
      "sha256": "0a1b2c...",
      "sizeBytes": 134217728,
      "installTo": "<drive>:\\XXMI"
    },
    "wwmi": {
      "version": "2.4.0",
      "downloadUrl": "https://cdn.example.com/wwmi/wwmi-2.4.0.zip",
      "sha256": "deadbeef...",
      "sizeBytes": 83886080,
      "installTo": "<drive>:\\XXMI\\WWMI",
      "loaderExe": "WWMI Loader.exe",
      "gameVersion": "2.4.0",
      "compatibleGameVersions": ["2.4.0", "2.4.1"]
    }
  }
}
```

### 术语表
- **XXMI**: 多游戏通用 mod 注入器框架（底层为 3Dmigoto 系）
- **WWMi**: Wuthering Waves Model Importer，XXMI 的鸣潮游戏包，含 `WWMI Loader.exe` 与 `Mods` 文件夹
- **MI 文件夹（3Dmigoto 文件夹）**: JASM 设置中指向含 loader exe 与 `d3dx_user.ini` 的目录，即 `XXMI\WWMI`
- **Mods 文件夹**: JASM 设置中指向 `XXMI\WWMI\Mods`，mod 按角色分子目录存放
- **Elevator**: JASM 现有的提权子进程机制

### 参考
- 现有首次启动页 `Views/StartupPage.xaml`、`ViewModels/StartupViewModel.cs`
- 现有路径配置 `ModManagerOptions`（`GimiRootFolderPath` / `ModsFolderPath`）
- 游戏配置 `Assets/Games/WuWa/game.json`（`GameModelImporterExeName` 等字段）
- 现有提权机制 `Services/ElevatorService.cs`
